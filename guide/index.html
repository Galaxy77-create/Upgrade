Карта экранов

Плоская структура: всё важное — в один-два тапа от главного экрана. Нижняя навигация из трёх вкладок, крупные зоны нажатия в нижней половине экрана для управления одной рукой.

Вкладка «Сегодня»

Единственная точка входа каждый день. Показывает только то, что нужно сделать сейчас.

Вкладка «Программа»

Три дня в виде таймлайна: пройденные, текущий и закрытый «завтра» — интрига для возврата.

Вкладка «Прогресс»

Серия, достижения, статистика. Здесь же — постоянная ненавязчивая ссылка на марафон.

Правила онбординга

  • Выбор варианта = автопереход через 300 мс
  • Кнопка «Назад» и возможность изменить ответ позже
  • Замеры можно пропустить — данные хранятся только у пользователя и не публикуются
  • Каждый ответ сохраняется на сервере сразу — закрыла и вернулась без потерь
  • Событие onboarding_completed уходит в бот

Персонализация

Цель → тексты мотивации и акцент тренировок. Уровень → версия тренировки (лёгкая / базовая / продвинутая). Формат → домашний или зальный набор упражнений.

Как открываются дни

Новый день открывается по календарю (в часовом поясе пользователя), а не сразу — так формируется привычка возвращаться. Пропустила день — программа не «сгорает»: текущий день остаётся доступным, серия просто не растёт.

Персональная мотивация дня 2 — по цели

Похудеть

«Вчера ты начала. Сегодня — главное не скорость, а регулярность».

Подтянуть живот

«Мышцы кора любят повторение. Второй день — это и есть повторение».

Вернуться к спорту

«Ты уже вернулась — вчера. Сегодня просто продолжаем».

10 · UX удержания и конверсии

Как довести до конца
и до оплаты

Главный враг лид-магнита — «открыла и забыла». Каждая механика ниже отвечает на вопрос: почему человек вернётся завтра?

Удержание

  • Маленький первый шаг. Первое задание — 12 минут, не час.
  • Незавершённое кольцо. 75% — сильный стимул закрыть день.
  • Напоминания в боте в выбранное время: утро — тренировка, вечер — отчёт.
  • Интрига завтрашнего дня: «Завтра Настя покажет упражнение для…»
  • Восстановление после пропуска: без наказания, тёплый текст «вернёмся вместе».
  • Сохранение на сервере: открыла с другого устройства — всё на месте.

Конверсия

  • Продажа на пике эмоции — после тренировки и на финале.
  • Бесшовная оплата в Telegram (Payments / ЮKassa) без выхода из приложения.
  • Бонус за прохождение: например, промокод для завершивших 3 дня (настраивается в админке).
  • Социальное доказательство: реальные отзывы участниц марафона.
  • Сегментный дожим в боте — разный текст тем, кто кликнул, и тем, кто нет.
  • Связь с целью: «Твоя цель — подтянуть живот. В марафоне на это — 21 день».

Безопасный вход в один тап

Сервер никогда не доверяет user_id, переданному клиентом. Личность подтверждается подписью Telegram initData, проверяемой на бэкенде через HMAC-SHA256 с токеном бота.

Что предусмотрено

  • Авторизация через Telegram WebApp initData (проверка подписи и срока)
  • Индивидуальная ссылка: t.me/bot/diary?startapp=src_reels
  • Прогресс и ответы хранятся на сервере
  • Исходящий webhook событий в бот (с подписью)
  • Напоминания через Bot API с учётом часового пояса
  • Источник: start-параметр + UTM при открытии в браузере
  • Покупка подтверждается только серверным webhook оплаты
  • Браузер без Telegram: Login Widget или одноразовая ссылка из бота

Проверка initData на сервере (TypeScript)

import crypto from "node:crypto";

export function verifyInitData(initData: string, botToken: string) {
  const params = new URLSearchParams(initData);
  const hash = params.get("hash"); params.delete("hash");
  const dataCheck = [...params].sort(([a], [b]) => a.localeCompare(b))
    .map(([k, v]) => `${k}=${v}`).join("\n");
  const secret = crypto.createHmac("sha256", "WebAppData").update(botToken).digest();
  const calc = crypto.createHmac("sha256", secret).update(dataCheck).digest("hex");
  const fresh = Date.now() / 1000 - Number(params.get("auth_date")) < 86400;
  if (!hash || calc !== hash || !fresh) throw new Error("Invalid Telegram auth");
  return JSON.parse(params.get("user")!);   // доверяем только после проверки
}

Все метрики считаются из одной таблицы событий. Каждый шаг воронки — отношение уникальных пользователей с событием к пользователям предыдущего шага, с разрезом по источнику трафика.
